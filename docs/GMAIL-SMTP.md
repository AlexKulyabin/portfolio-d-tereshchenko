# Уведомления о заявках на Gmail

После настройки на каждую новую заявку сайта придёт письмо на выделенный ящик Gmail.
Отправка работает на сервере Firebase: пароль от почты не попадает в браузер, код сайта
или GitHub.

## Что должен сделать владелец почты

1. Выберите отдельный Gmail-ящик, на который должны приходить заявки. Лучше создать
   ящик, принадлежащий бизнесу, а не личный ящик сотрудника.
2. Включите для него двухэтапную аутентификацию Google.
3. Откройте страницу [паролей приложений Google](https://myaccount.google.com/apppasswords).
4. Создайте пароль приложения с понятным названием, например `Сайт expert-auditor`.
5. Google покажет 16-значный пароль приложения. Передайте его разработчику безопасным
   способом. Не отправляйте пароль от самого Gmail-ящика.

Пароль приложения работает только при включённой двухэтапной аутентификации. Если
позже сменить основной пароль Google, пароль приложения будет отозван — тогда нужно
создать новый и обновить секрет Firebase.

Официальная справка Google: [пароли приложений](https://support.google.com/mail/answer/185833).

## Что делает разработчик

Cloud Functions работают только на тарифе Firebase **Blaze**. Перед первым деплоем
владелец Firebase-проекта должен подключить биллинг и установить предупреждение о
бюджете. При небольшом количестве заявок стоимость обычно укладывается в бесплатные
квоты, но сама возможность запуска Functions требует платёжный аккаунт.

При первом деплое Firebase включит необходимые API Cloud Functions и Cloud Run. Если
у аккаунта нет права на включение API или подключение биллинга, это должен сделать
владелец Firebase-проекта в консоли Google Cloud.

В корне проекта выполните команды — значения вводятся скрыто и не записываются в
репозиторий:

```bash
firebase functions:secrets:set GMAIL_SMTP_USER
firebase functions:secrets:set GMAIL_SMTP_APP_PASSWORD
firebase deploy --only functions:sendLeadEmail
```

В `GMAIL_SMTP_USER` укажите полный адрес Gmail-ящика, например
`expert.auditor.notifications@gmail.com`. В `GMAIL_SMTP_APP_PASSWORD` — 16-значный пароль
приложения, полученный на предыдущем шаге; пробелы можно не вводить.

Функция запускается только при создании новой заявки в Firestore (`leads/{leadId}`).
Она отправляет письмо на тот же Gmail-ящик, а если посетитель оставил корректный e-mail,
делает его адресом ответа в письме.

## Проверка после деплоя

1. Откройте сайт в приватном окне и отправьте тестовую заявку.
2. Подождите до одной минуты и проверьте входящие Gmail, включая папку «Спам».
3. В Firebase Console откройте Functions → `sendLeadEmail` → Logs. Там должна быть
   запись `Lead notification sent` без содержимого заявки.
4. Ответьте на тестовое письмо: ответ должен уйти на e-mail, указанный в заявке.

## Персональные данные

Письмо содержит имя, телефон, почту и комментарий посетителя. После включения этой
функции данные передаются в Gmail (Google) для уведомления Оператора. Перед запуском
покажите обновлённые политику и согласие на обработку персональных данных юристу.
Это особенно важно, поскольку проект уже хранит заявки в Firebase за пределами РФ.
