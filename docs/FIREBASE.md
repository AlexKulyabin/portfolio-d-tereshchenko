# Настройка Firebase и развёртывание

Пошагово: от пустого аккаунта Google до работающего сайта на своём домене.
Проходится один раз примерно за полчаса.

---

## 1. Создать проект

1. Откройте [console.firebase.google.com](https://console.firebase.google.com) и
   войдите под аккаунтом Google, который останется у владельца сайта.
2. «Создать проект», задайте имя (например `tereshchenko-site`).
3. Google Analytics можно отключить — сайт использует Яндекс.Метрику.

## 2. Подключить нужные сервисы

**Authentication.** Раздел Authentication → «Начать» → способ входа «Электронная
почта / пароль» → включить. Второй переключатель, «Ссылка для входа», не нужен.

**Firestore Database.** Раздел Firestore → «Создать базу данных» → режим
**Production mode** → регион `eur3 (europe-west)`. Правила зальются из файла на
шаге 6, поэтому стартовые можно оставить любыми.

**Storage.** Раздел Storage → «Начать» → тот же регион.

Storage может потребовать тарифный план Blaze (с привязанной картой). Для этого
проекта расход остаётся в пределах бесплатного лимита: контент — файл на 26 КБ,
изображения — единицы мегабайт. Установите в биллинге предупреждение о превышении
бюджета, чтобы быть спокойным.

## 3. Создать веб-приложение и получить ключи

Настройки проекта (шестерёнка) → «Ваши приложения» → значок `</>` → задайте имя →
«Зарегистрировать приложение».

Firebase покажет объект `firebaseConfig`. Перенесите значения в файл `.env.local`
в корне проекта (создайте его копированием `.env.example`):

```
VITE_FIREBASE_API_KEY=AIza...
VITE_FIREBASE_AUTH_DOMAIN=ваш-проект.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=ваш-проект
VITE_FIREBASE_STORAGE_BUCKET=ваш-проект.firebasestorage.app
VITE_FIREBASE_MESSAGING_SENDER_ID=123456789012
VITE_FIREBASE_APP_ID=1:123456789012:web:abc123
VITE_SITE_URL=https://ваш-домен.ру
VITE_USE_EMULATORS=false
```

Значение `VITE_FIREBASE_STORAGE_BUCKET` возьмите ровно таким, как показывает консоль:
у новых проектов это `имя.firebasestorage.app`, у старых — `имя.appspot.com`.

Эти ключи не секретны: они попадают в код сайта и видны любому посетителю. Доступ к
данным ограничивают правила, а не сокрытие ключей. Файл `.env.local` всё равно не
попадает в репозиторий — там могут появиться и настоящие секреты.

## 4. Создать администратора

Authentication → «Users» → «Add user». Укажите почту и пароль владельца сайта.
Скопируйте `User UID` — он понадобится на следующем шаге.

## 5. Выдать права администратора

Правила требуют у пользователя метку `admin`. Проставить её из консоли Firebase
нельзя — нужен один запуск скрипта.

Создайте сервисный ключ: Настройки проекта → «Сервисные аккаунты» → «Создать закрытый
ключ» → скачается JSON-файл. **В репозиторий его не кладите.**

В отдельной временной папке:

```bash
npm init -y && npm install firebase-admin
```

Создайте там `set-admin.mjs`:

```js
import admin from 'firebase-admin'
import { readFile } from 'node:fs/promises'

const key = JSON.parse(await readFile('./serviceAccount.json', 'utf8'))
admin.initializeApp({ credential: admin.credential.cert(key) })

const uid = process.argv[2]
await admin.auth().setCustomUserClaims(uid, { admin: true })
console.log('Права администратора выданы:', uid)
```

Положите рядом скачанный ключ под именем `serviceAccount.json` и выполните:

```bash
node set-admin.mjs ВСТАВЬТЕ_USER_UID
```

После этого удалите папку вместе с ключом. Права выданы навсегда; повторять нужно
только если появится второй администратор.

Если пользователь в этот момент был в админке, ему нужно выйти и войти заново —
метка попадает в токен при входе.

## 6. Залить правила доступа

Установите Firebase CLI, если его нет:

```bash
npm install -g firebase-tools
```

Войдите и свяжите папку с проектом:

```bash
firebase login
firebase use --add
```

Выберите свой проект и задайте псевдоним `default`.

Залейте правила:

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
```

Без этого шага админка не сможет ни читать, ни сохранять: стартовые правила
Firestore запрещают всё.

## 7. Первая публикация контента

```bash
npm run dev
```

Откройте `http://localhost:5173/admin`, войдите под созданной учётной записью.
Админка покажет стартовое наполнение. Нажмите «Сохранить», затем «Опубликовать» —
контент запишется в базу и выложится файлом, который читает сайт.

Дальше заполняйте разделы по подсказкам на экране «Обзор»: он показывает, чего
не хватает для запуска.

## 8. Собрать и выложить сайт

```bash
npm run deploy
```

Команда скачает свежий контент, соберёт статику, отрисует страницы и выложит их на
Firebase Hosting. Сайт откроется по адресу `https://ваш-проект.web.app`.

Только статика, без правил:

```bash
npm run deploy:hosting
```

Уведомления о новых заявках в Gmail настраиваются отдельно: потребуется тариф Blaze
и пароль приложения Google. Порядок — в [GMAIL-SMTP.md](GMAIL-SMTP.md).

## 9. Подключить свой домен

Hosting → «Добавить пользовательский домен» → введите домен → Firebase покажет
записи DNS, которые нужно прописать у регистратора.

Обычно это две записи `A` для корневого домена и одна `CNAME` для `www`. Сертификат
HTTPS выпускается автоматически, обычно в течение часа, иногда до суток.

После подключения домена укажите его в админке (Контакты и настройки → Адрес сайта)
и пересоберите сайт — по этому адресу строятся ссылки для поисковых систем и
`sitemap.xml`.

Если домен зарегистрирован в Reg.ru, передайте заказчику
[инструкцию для Reg.ru](DOMAIN-REG-RU.md). Полный порядок со стороны Firebase,
включая проверку прав администратора и публикацию контента, — в
[FIREBASE-PUBLICATION.md](FIREBASE-PUBLICATION.md).

## 10. Автоматическая публикация из репозитория (необязательно)

В репозитории есть готовый сценарий `.github/workflows/deploy.yml`: он проверяет типы
и собирает сайт на каждое изменение, а при попадании в ветку `main` публикует его.
Чтобы он заработал, нужно один раз добавить настройки в GitHub.

**Переменные** (Settings → Secrets and variables → Actions → вкладка Variables).
Те же значения, что в `.env.local`, кроме `VITE_USE_EMULATORS`:

`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`,
`VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`,
`VITE_FIREBASE_APP_ID`, `VITE_SITE_URL`.

**Секрет** (вкладка Secrets) — `FIREBASE_SERVICE_ACCOUNT`. Значение: содержимое JSON-файла
сервисного ключа целиком. Получить проще всего командой в папке проекта:

```bash
firebase init hosting:github
```

Она создаст сервисный аккаунт и сама добавит секрет в репозиторий.

Пока настройки не добавлены, публиковать можно вручную командой `npm run deploy` —
сценарий этому не мешает.

## 11. Резервные копии

Контент невелик, но терять его неприятно. Простой вариант — раз в месяц открыть
`https://ваш-проект.firebasestorage.app/v0/b/ВАШ_BUCKET/o/public%2Fcontent.json?alt=media`
и сохранить файл. Из него восстанавливается всё наполнение сайта.

Автоматические копии Firestore настраиваются в разделе Firestore → «Резервные копии»
(доступно на плане Blaze).

Дополнительно админка хранит десять последних опубликованных версий: вернуть любую
можно на экране «Обзор».

## Если что-то не работает

**«Firebase не настроен»** в админке — не заполнен `.env.local` или сервер разработки
запущен до его создания. Перезапустите `npm run dev`.

**«Missing or insufficient permissions»** — не залиты правила (шаг 6) или пользователю
не выдана метка `admin` (шаг 5). Проверьте: выйдите из админки и войдите заново.

**Изображение не загружается** — проверьте, что Storage подключён и правила залиты.
В консоли браузера будет видно, какой запрос отклонён.

**Сайт не видит опубликованный контент** — откройте адрес `content.json` из раздела 11
в браузере. Если файл не отдаётся, значит правила Storage не залиты.

**`npm run build` пишет «беру стартовое наполнение»** — сборка не смогла скачать
контент. Проверьте `VITE_FIREBASE_STORAGE_BUCKET` в `.env.local` и что публикация из
админки была хотя бы раз. Сборка при этом не прерывается, но в HTML попадут исходные
тексты вместо ваших.
