# Чек-лист запуска

Порядок действий от готового кода до работающей рекламы. Пункты идут в том порядке,
в котором их удобнее выполнять.

---

## 1. Firebase и домен

- [ ] Проект Firebase создан, сервисы подключены — [FIREBASE.md](FIREBASE.md)
- [ ] Правила залиты: `firebase deploy --only firestore:rules,storage:rules`
- [ ] Администратор создан, метка `admin` выдана
- [ ] Домен подключён к Hosting, HTTPS работает
- [ ] Проверено, что `www.домен.ру` открывается и ведёт на основной адрес

## 2. Содержимое

- [ ] На экране «Обзор» в админке не осталось незакрытых пунктов
- [ ] Телефон, почта, мессенджеры заполнены и проверены нажатием
- [ ] Реквизиты заполнены (нужны для модерации рекламы)
- [ ] Цены проставлены во всех трёх пакетах каждой услуги
- [ ] Фотография эксперта загружена
- [ ] **Нормативные ссылки на страницах услуг вычитаны экспертом** — номера приказов,
      статей и сроки
- [ ] Адрес сайта указан в настройках, сайт пересобран после этого

## 3. Проверка перед публикацией

- [ ] Все три страницы услуг открываются, цены и сроки верные
- [ ] Форма заявки отправляется, заявка видна в разделе «Заявки»
- [ ] Кнопка звонка на телефоне действительно звонит
- [ ] Ссылки на Telegram и WhatsApp открываются
- [ ] Сайт проверен на телефоне, а не только на компьютере
- [ ] Политика конфиденциальности и согласие открываются, реквизиты в них подставились
- [ ] `sitemap.xml` и `robots.txt` доступны по прямым адресам

## 4. Персональные данные

- [ ] Уведомление в Роскомнадзор подано — [PERSONAL-DATA.md](PERSONAL-DATA.md)
- [ ] Тексты политики и согласия проверены юристом

## 5. Яндекс.Метрика

- [ ] Счётчик создан, его номер вписан в админке
- [ ] Через сутки проверено, что визиты фиксируются
- [ ] Вебвизор включён
- [ ] Настроены цели — **до** запуска рекламы, иначе Директ не сможет обучать
      автостратегии:

| Идентификатор цели | Когда срабатывает |
| --- | --- |
| `form_submit` | Отправлена заявка |
| `click_phone` | Нажат телефон |
| `click_email` | Нажата почта |
| `click_whatsapp` | Нажат WhatsApp |
| `click_telegram` | Нажат Telegram |

Цели создаются в Метрике с типом «JavaScript-событие», идентификатор вводится ровно
как в таблице.

## 6. Яндекс.Вебмастер и Google Search Console

- [ ] Сайт добавлен в Вебмастер, права подтверждены мета-тегом (поле в админке —
      «Код подтверждения в Яндекс.Вебмастере»)
- [ ] `sitemap.xml` добавлен в Вебмастере
- [ ] Регион сайта указан
- [ ] То же самое в Google Search Console
- [ ] Через несколько дней проверено, что страницы попали в индекс

## 7. Яндекс.Директ

Перед запуском убедитесь, что на сайте есть всё, что проверяет модерация:

- [ ] Наименование или ИНН — в подвале
- [ ] Телефон — в шапке и подвале
- [ ] Политика обработки персональных данных
- [ ] Отметка согласия в форме

Дальше:

- [ ] Отдельная группа объявлений на каждую услугу, каждая ведёт на свою страницу
- [ ] В ссылках объявлений проставлены UTM-метки — они сохраняются вместе с заявкой,
      и в разделе «Заявки» будет видно, какое объявление сработало
- [ ] Метрика привязана к кампании
- [ ] Отслеживание конверсий настроено на цель `form_submit`

## 8. После запуска

Первая неделя:

- [ ] Заявки доходят, телефон в них корректный
- [ ] В Вебвизоре посмотрено несколько записей: где посетители останавливаются
- [ ] Проверен показатель отказов по каждой посадочной странице

Дальше:

- [ ] Раз в месяц — резервная копия контента ([FIREBASE.md](FIREBASE.md), раздел 10)
- [ ] Раз в квартал — проверка актуальности нормативных ссылок, законодательство
      меняется
- [ ] Раз в полгода — `npm audit` и обновление зависимостей

---

## Быстрая проверка скорости

Откройте [PageSpeed Insights](https://pagespeed.web.dev) и введите адрес сайта.
Ориентиры для мобильной версии:

| Показатель | Цель |
| --- | --- |
| Performance | 90 и выше |
| LCP | меньше 2,5 с |
| CLS | меньше 0,1 |

Если показатели просели — почти всегда виноваты изображения. Проверьте, что они
загружались через админку: она сама переводит их в WebP и сжимает.
