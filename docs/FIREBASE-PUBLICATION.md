# Инструкция для разработчика: Firebase, домен и публикация

Проект Firebase: `website-df769`  
Временный публичный адрес: `https://website-df769.web.app`  
Целевой домен: `https://expert-auditor.com`

Сейчас `expert-auditor.com` показывает парковочную страницу Reg.ru. Пока домен не
будет подключён к Firebase Hosting, заказчик не увидит публикации по своему адресу.

## 1. Подключить корневой домен в Firebase Hosting

1. Откройте [Firebase Console](https://console.firebase.google.com/) под аккаунтом,
   которому принадлежит проект `website-df769`.
2. Откройте **Hosting** и выберите сайт `website-df769`.
3. Нажмите **Добавить пользовательский домен**.
4. Укажите `expert-auditor.com`.
5. Не закрывайте мастер: он покажет точные DNS-записи для подтверждения владения и
   направления домена на Hosting.
6. Скопируйте эти записи в таблицу и передайте заказчику вместе с
   [инструкцией для Reg.ru](DOMAIN-REG-RU.md).
7. Когда заказчик подтвердит изменения, в мастере Firebase нажмите проверку записей
   и дождитесь статуса **Connected**.

Значения записей не фиксируем в репозитории: Firebase показывает их индивидуально,
а при повторном создании подключения они могут измениться.

После подключения корневого домена добавьте `www.expert-auditor.com` вторым доменом
и настройте перенаправление на `expert-auditor.com`. Не создавайте `A` и `CNAME` для
одного имени одновременно. Firebase автоматически выпустит SSL-сертификат; процесс
может занять до 24 часов.

Справка Firebase: [подключение собственного домена](https://firebase.google.com/docs/hosting/custom-domain).

## 2. Проверить доступ администратора

Админка доступна по адресу `https://website-df769.web.app/admin` (после подключения
домена также по `https://expert-auditor.com/admin`). Пользователь должен быть создан
в Firebase Authentication с методом **Email/Password** и иметь custom claim:

```json
{ "admin": true }
```

Выдать claim можно по шагу 5 из [FIREBASE.md](FIREBASE.md). После выдачи пользователь
должен полностью выйти из админки и войти снова, чтобы обновился токен.

Если при сохранении, публикации или загрузке фото появляется `Missing or insufficient
permissions`, сначала проверяйте claim, а затем правила доступа.

## 3. Опубликовать правила Firestore и Storage

Из корня проекта выполните:

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
```

Команда загружает [firestore.rules](../firestore.rules),
[storage.rules](../storage.rules) и индексы. Она не публикует сайт и не меняет
содержимое Firestore или Storage.

Важная деталь: `storage:rules` не является корректной целью для используемой версии
Firebase CLI. Для Storage нужна цель `storage`.

## 4. Как фактически публикуются текст и изображения

### Текст, цены и ссылки

1. Откройте админку.
2. Внесите изменения в нужном разделе.
3. Нажмите **Опубликовать** в верхней панели. Одна кнопка **Сохранить** записывает
   только черновик и не меняет сайт.

При публикации админка создаёт новую версию в Firestore и перезаписывает объект
`public/content.json` в bucket `website-df769.firebasestorage.app`. Публичный сайт
забирает этот JSON после загрузки страницы, поэтому обычный посетитель увидит изменения
после обновления страницы; кеш контента действует до минуты.

### Фото эксперта и документы

1. Откройте в админке **Об эксперте**.
2. Загрузите фото эксперта или скан документа.
3. Заполните описание изображения.
4. Нажмите **Опубликовать**.

Файлы загружаются в Storage сразу, но до нажатия **Опубликовать** публичный контент
не содержит ссылку на новый файл. Пути файлов: `expert/...webp` для фото и
`credentials/...webp` для документов. Картинка сжимается и конвертируется в WebP в
браузере.

## 5. Опубликовать статический HTML после смены домена

После статуса **Connected**:

1. В админке заполните поле «Адрес сайта»: `https://expert-auditor.com`.
2. Нажмите **Опубликовать**.
3. В корне репозитория выполните:

```bash
npm run deploy
```

Эта команда забирает последнюю версию контента, собирает и пререндерит сайт, создаёт
`sitemap.xml`, затем публикует Hosting. Она нужна один раз после смены домена и далее
после изменений, которые должны попасть в исходный HTML для поисковых роботов.

Если в проект добавлена функция почтовых уведомлений, перед этой командой настройте
secrets Gmail по [GMAIL-SMTP.md](GMAIL-SMTP.md): `npm run deploy` публикует и
Cloud Functions.

Для обычных текстовых изменений и фотографий отдельная сборка не обязательна: после
публикации в админке их подтягивает браузер. Однако мета-теги, микроразметка и HTML
для поисковых роботов обновятся только после `npm run deploy`.

## 6. Контрольная проверка

Проверьте по порядку:

- Firebase Hosting показывает для `expert-auditor.com` статус **Connected**;
- `https://expert-auditor.com` открывает сайт, не парковку Reg.ru;
- `https://expert-auditor.com/admin` открывает форму входа;
- после тестовой публикации в `public/content.json` увеличилась версия;
- новое фото видно на сайте в приватном окне браузера;
- `https://expert-auditor.com/sitemap.xml` доступен и содержит адреса с
  `expert-auditor.com`.

Публичный JSON можно проверить без входа в Firebase:

```text
https://firebasestorage.googleapis.com/v0/b/website-df769.firebasestorage.app/o/public%2Fcontent.json?alt=media
```
